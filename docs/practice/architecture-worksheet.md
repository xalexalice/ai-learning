# AI 应用架构工作表

以一个具体可运行项目为背景；纯设计练习要在开头标明。每项假设写单位、依据、验证方法与状态。

## 需求与约束

| 方面 | 记录内容 |
| --- | --- |
| 用户 | 身份来源、租户、角色、文档读写范围 |
| 数据 | 总量、大小、版本、更新/删除频率、授权条件 |
| 流量 | 平均/峰值 QPS、输入输出长度、在途与执行并发 |
| 服务目标 | 完整成功、延迟、质量、费用、生效窗口 |
| 运行条件 | 团队、现有系统、资源、依赖可用性 |

## 两条数据流

分别画“文档入库/更新/撤权/删除”和“用户请求/检索/生成/工具执行”。每个箭头标身份、版本、输出和失败。写清索引更新滞后时读层怎样阻止越权和已删除文档。

## 容量与成本

平均在途请求约等于到达率 × 平均停留时间，写稳定性前提；执行槽位和排队量需要测量。向量存储先算数量 × 维度 × 每元素字节，再加文本、元数据、索引、副本和版本。费用写假设费率或真实账单日期，按成功任务计入重试和工具。

## 一份方案选择记录

| 项 | 填写内容 |
| --- | --- |
| 决策 | 具体选择与涉及组件 |
| 约束 | 需要解决的真实问题及依据 |
| 可选方案 | 至少一个合理替代及代价 |
| 验证 | 已有数据或待执行实验 |
| 边界 | 失败方式、一致性窗口、运维负担 |
| 重审触发 | 什么测量或需求变化会改变选择 |

## 故障与交付

逐项说明超时、断流、取消、重复工具写入、缓存过期、授权变化、队列过载、模型/索引版本不匹配。写 SLI 分母、SLO 窗口、错误预算、告警动作、降级与回滚，不把任意阈值当实测。

记录启动方式、监控、负责人、配置/数据许可与回滚验证。没有执行发布或故障演练的项保留“未执行”。
